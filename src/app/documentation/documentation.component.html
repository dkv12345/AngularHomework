Tổng Quan Kiến Trúc Angular & Tổ Chức Dự Án

Angular là một nền tảng SPA (Single Page Application) hướng component. Dự án này áp dụng đầy đủ các mẫu thiết kế chuẩn của Angular doanh nghiệp: Separation of Concerns (SOC), Dependency Injection (DI), và Reactive Programming (RxJS).

1

Angular Service & Singleton Pattern

Service đảm nhiệm việc xử lý logic nghiệp vụ và lưu trữ / truy xuất dữ liệu. Decorator @Injectable({{ '{' }} providedIn: 'root' {{ '}' }}) đăng ký service vào Root Injector, biến nó thành một Singleton instance (duy nhất 1 phiên bản trong toàn bộ vòng đời ứng dụng).

2

Dependency Injection (DI)

Component không tự khởi tạo service bằng từ khóa new ProductService(). Thay vào đó, Angular DI tự động truyền phiên bản service thông qua tham số của Constructor: constructor(private pservice: ProductService) {{ '{' }} {{ '}' }}.

3

Data Binding Mechanism

Angular hỗ trợ 4 cơ chế ràng buộc dữ liệu:

  • Interpolation: {{ '{{' }} p.ProductName {{ '}}' }} (chèn giá trị từ TS ra HTML).
  • Property Binding: [src]="p.Image" (gán giá trị cho thuộc tính DOM).
  • Event Binding: (click)="viewDetail(p)" (bắt sự kiện click của người dùng).
  • Two-way Binding: [(ngModel)]="searchTerm" (đồng bộ 2 chiều dữ liệu input & biến).

Exercise 13: JSON Array Model – Product Event & Parameterized Routing

Mục tiêu bài tập: Khai báo mảng sản phẩm trong ProductService, hiển thị danh sách dạng bảng, và khi nhấp "Details" sẽ chuyển sang trang chi tiết với route chứa tham số ID.

Sơ đồ luồng hoạt động (Data & Navigation Flow):

Bước 1 ProductService

Khai báo productsImage[] và cung cấp 2 method getProductsWithImages() và getProductDetail(id).

→
Bước 2 ProductListComponent

Inject service qua constructor, lấy mảng sản phẩm gán vào biến products, render bảng với *ngFor.

→
Bước 3 Event (click)

User click link "Details" → gọi viewDetail(p) → thực thi router.navigate(['service-product-image-event', p.ProductId]).

→
Bước 4 DetailComponent

Đọc tham số qua ActivatedRoute.paramMap.subscribe() → gọi _fs.getProductDetail(id) → hiển thị.

Giải thích từng đoạn mã quan trọng (Code Breakdown):

1. Cấu hình Routing với Route Parameter (app-routing-module.ts)
{{ '{' }} path: 'service-product-image-event', component: ServiceProductImageEventComponent {{ '}' }},
{{ '{' }} path: 'service-product-image-event/:id', component: ServiceProductImageEventDetailComponent {{ '}' }},

Giải thích:

  • :id là một Route Parameter (tham số động). Khi URL là /service-product-image-event/p1, Angular Router nhận diện giá trị của :id là chuỗi "p1".
  • Khi URL khớp với mẫu trên, Angular sẽ tự động tải và kích hoạt ServiceProductImageEventDetailComponent vào thẻ <router-outlet>.
2. Lấy tham số ID từ URL (service-product-image-event-detail.component.ts)
constructor(
  private activateRoute: ActivatedRoute,
  private _fs: ProductService,
  private router: Router
) {{ '{' }}
  this.activateRoute.paramMap.subscribe((param) => {{ '{' }}
    let id = param.get('id');
    if (id != null) {{ '{' }}
      this.selectedProduct = this._fs.getProductDetail(id);
    {{ '}' }}
  {{ '}' }});
{{ '}' }}

Giải thích:

  • ActivatedRoute: Service do Angular cung cấp chứa toàn bộ thông tin về route hiện tại.
  • paramMap: Một Observable phát ra bản đồ các tham số URL mỗi khi route thay đổi.
  • subscribe(...): Đăng ký lắng nghe sự thay đổi. Khi người dùng chuyển từ sản phẩm p1 sang p2 mà không reload trang, hàm callback vẫn được kích hoạt tự động để cập nhật selectedProduct.
  • param.get('id'): Lấy giá trị tương ứng với placeholder :id đã cấu hình trong routes.
3. Nút Go Back (Trở về trang danh sách)
goBack() {{ '{' }}
  this.router.navigate(['service-product-image-event']);
{{ '}' }}

Giải thích: this.router.navigate(['...']) cho phép điều hướng bằng mã TypeScript mà không cần tải lại toàn bộ trang (giữ trọn vẹn trạng thái Single Page Application).

Exercise 18: JSON Array Model – Group Customers (HTTP Service & Observable)

Mục tiêu bài tập: Tách biệt dữ liệu tĩnh ra tệp bên ngoài assets/data/customers.json, sử dụng Angular HttpClient để gọi bất đồng bộ lấy dữ liệu, xử lý nhóm khách hàng (VIP và Normal), và render lên bảng nhóm.

1. Vì sao dùng HttpClient thay vì gán mảng cứng?

Trong các ứng dụng thực tế, dữ liệu đến từ máy chủ REST API backend hoặc cơ sở dữ liệu. HttpClient giả lập chính xác luồng giao tiếp mạng qua giao thức HTTP (GET, POST, PUT, DELETE), giúp ứng dụng có tính module hóa cao và sẵn sàng kết nối API thật.

2. Khái niệm Observable & RxJS Stream

this.http.get(...) trả về một Observable (luồng dữ liệu bất đồng bộ). Khác với Promise chỉ trả về 1 kết quả duy nhất, Observable có thể được xử lý qua các toán tử (operators) như pipe(), retry(), catchError() để tự động thử lại khi mạng chập chờn.

Triển khai Service với HttpClient (customer.service.ts)
@Injectable({{ '{' }} providedIn: 'root' {{ '}' }})
export class CustomerService {{ '{' }}
  private readonly dataUrl = 'assets/data/customers.json';

  constructor(private http: HttpClient) {{ '{' }} {{ '}' }}

  getCustomerGroups(): Observable<CustomerTypeGroup[]> {{ '{' }}
    return this.http.get<CustomerTypeGroup[]>(this.dataUrl).pipe(
      retry(1), // Thử lại 1 lần nếu mất kết nối
      catchError((error) => {{ '{' }}
        console.error('Lỗi tải dữ liệu:', error);
        return of(this.fallbackData); // Dùng fallback nếu lỗi
      {{ '}' }})
    );
  {{ '}' }}
{{ '}' }}
Subcribe dữ liệu trong Component (service-group-customer.component.ts)
ngOnInit(): void {{ '{' }}
  this.isLoading = true;
  this.customerService.getCustomerGroups().subscribe({{ '{' }}
    next: (data) => {{ '{' }}
      this.customerGroups = data;
      this.isLoading = false;
    {{ '}' }},
    error: (err) => {{ '{' }}
      this.errorMessage = 'Không thể tải dữ liệu khách hàng';
      this.isLoading = false;
    {{ '}' }}
  {{ '}' }});
{{ '}' }}

Giải thích hàm subscribe():

  • next: (data) => ...: Được kích hoạt khi HTTP request hoàn tất thành công và trả về JSON đã được parse tự động thành mảng đối tượng.
  • error: (err) => ...: Bắt lỗi nếu mạng đứt hoặc đường dẫn tệp JSON 404.
Ôn tập vấn đáp & Bảo vệ bài tập

Bộ Câu Hỏi Phỏng Vấn / Vấn Đáp Điển Hình (Q&A)

Các câu hỏi giảng viên thường hỏi khi chấm bài tập kèm câu trả lời chuẩn xác, súc tích để bạn tự tin giải thích.

Q1: Tại sao nên khai báo dữ liệu trong Service thay vì khai báo trực tiếp trong Component?
Trả lời: Để tuân thủ nguyên lý Separation of Concerns (Tách biệt mối quan tâm). Component chỉ chịu trách nhiệm điều khiển giao diện (View), còn Service chịu trách nhiệm xử lý logic nghiệp vụ và truy xuất dữ liệu. Việc dùng Service giúp tái sử dụng dữ liệu giữa nhiều component khác nhau (ví dụ List và Detail cùng dùng chung ProductService) và dễ dàng kiểm thử (Unit Testing).
Q2: @Injectable({{ '{' }} providedIn: 'root' {{ '}' }}) có ý nghĩa gì?
Trả lời: Cú pháp này khai báo rằng service này được đăng ký ở cấp cao nhất (Root Module). Angular sẽ tự động tạo một phiên bản duy nhất (Singleton) cho toàn ứng dụng và tối ưu hóa đóng gói (Tree-shaking: nếu service không được dùng ở đâu thì compiler sẽ loại bỏ khỏi bản build).
Q3: Phân biệt giữa [src]="p.Image" và src="{{ '{{' }}p.Image{{ '}}' }}"?
Trả lời: Cả hai đều đạt kết quả hiển thị hình ảnh giống nhau. Tuy nhiên, [src]="p.Image" là Property Binding (ràng buộc trực tiếp vào thuộc tính DOM của thẻ HTML), còn src="{{ '{{' }}...{{ '}}' }}" là Interpolation (nội suy chuỗi). Trong các dự án Angular chuẩn, Property Binding được khuyến khích sử dụng hơn vì tính tường minh và an toàn kiểu dữ liệu.
Q4: Tại sao trong Component Detail cần dùng paramMap.subscribe() thay vì lấy snapshot?
Trả lời: Nếu dùng paramMap.get('id') qua snapshot, component chỉ đọc ID một lần khi khởi tạo. Khi người dùng bấm chuyển sang xem sản phẩm khác (cùng route detail nhưng đổi ID), Angular tái sử dụng lại component đó mà không hủy, dẫn tới snapshot không cập nhật. Dùng paramMap.subscribe() lắng nghe luồng Observable giúp giao diện tự động cập nhật ngay lập tức khi ID thay đổi.
Q5: Làm thế nào để cấu hình Angular nhận diện thư mục assets/data/customers.json?
Trả lời: Trong tệp cấu hình angular.json, thuộc tính "assets" được khai báo bao gồm thư mục "public" và "src/assets". Khi chạy ng serve hoặc ng build, Angular CLI sẽ tự động sao chép các tệp tĩnh vào thư mục gốc của web server, giúp chúng có thể truy cập thông qua HTTP GET tại http://localhost:4200/assets/data/customers.json.
